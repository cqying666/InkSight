# Engineering Constraints — InkSight 创作教练

> 此文件为开发实现前的工程约束门禁，所有代码实现必须遵守。变更需同步更新此文件。

## 1. 产品硬约束（来自 PRD 与项目记忆）

### 1.1 拆文引擎
- LLM 输出必须为强约束 JSON，符合 14 维度 schema（骨架层5 + 血肉层5 + 风格层4）
- 每个维度必须附带 evidence 原文引用，减少幻觉
- 类型识别置信度 <0.7 时标注 mixed 类型，加载通用权重
- 处方遵循"三不原则"：不替写具体文字、不给唯一答案、不做好坏评判
- 每个处方建议必须含：方向描述、适配性评分(1-5)、操作方法、参考案例、预期效果
- 降级：LLM 输出异常重试一次仍失败则提示重试；处方超时先展示拆解+诊断，处方异步加载

### 1.2 数据采集合规
- 仅采集各平台公开榜单页面信息，不采集付费内容正文
- 数据用于趋势统计分析，不存储和展示单篇作品完整内容
- 上线前需完成各平台 robots.txt 和反爬虫政策评估
- 处方"参考案例"初期用描述性引用而非原文引用

### 1.3 创作工作台
- 段落编号系统在编辑器与拆文分析间保持一致（写后分析无缝对应）
- 实时结构提示只提醒结构位置，不评价内容质量
- 提示轻量不打断心流：底部静态展示，不弹窗、不闪烁
- 接近计划反转位置时提示从灰色变为淡黄色

### 1.4 降级机制（PRD 6.3 节）
- 拆文：类型置信度<0.7→mixed+通用权重；LLM 异常→重试一次；处方超时→异步加载
- 趋势：采集失败→展示最近成功数据并标注"更新于 N 小时前"；某平台不可用→隐藏该列
- 素材：情境匹配无结果→降级关键词搜索；语义搜索超时→提示更具体关键词
- 创作工作台：实时提示失败→隐藏底部条；侧栏推荐失败→提示手动搜索

## 2. 质量阈值（PRD 6.1 节）
| 维度 | 阈值 |
|:-----|:-----|
| 拆解一致性（同篇拆5次核心维度标准差） | >85% |
| 类型识别准确率（与人工标注一致率） | >90% |
| 建议方向覆盖（5次拆解建议交集） | >70% |
| 反直觉发现质量（意外度×启发度） | 意外度>3.5 且 启发度>3.5（5分制） |
| 整体有用性（用户评分） | 均 >4 分（5分制） |
| 素材提取准确率（与人工判断一致率） | >80% |
| 情境匹配相关性（用户采纳率） | >20% |
| 趋势数据时效性（与实际榜单延迟） | <24 小时 |

## 3. 设计约束
- 视觉风格：Editorial 文学杂志风格（对齐落地页）
- 色板：seal red `#8B2635` / warm gold `#A87E3B` / ink black `#1A1614` / warm ivory paper background
- 字体：Google Fonts CDN（Cormorant Garamond + Inter + 思源宋体/黑体回退）
- 暖色调 + 衬线字体，避免"冷冰冰数据报告"感
- 三明治结构 + 创作者语言

## 4. 性能约束
- LLM 拆解响应：<30 秒
- 诊断规则引擎：毫秒级
- 处方生成：<8 秒
- 前端首屏 LCP：<2 秒
- 趋势数据采集延迟：<24 小时

## 5. 技术选型待定项（P0-T1 决策）
以下选型需在 P0-T1 完成后确定并回填：
- 前端框架：React / Vue / 其他
- 后端语言与框架：Node / Python / Go
- LLM 服务：OpenAI / Claude / 国产模型 / 自部署
- 主数据库：PostgreSQL / MySQL / 其他
- 向量数据库：Pinecone / Milvus / pgvector / 其他
- 部署形态：云服务 / 自建 / Serverless

## 6. 禁止变更项
- 落地页 `inksight-landing.html` 为参赛提交件，独立于产品代码，不纳入产品开发分支
- PRD 中标注 `[待确认]` 的定价需产品决策后才能实现付费逻辑
- PRD 中标注 `[待评估]` 的合规事项未完成评估前，相关功能不对外上线

## 7. 验证默认
- 每个 Phase 结束需对齐 PRD 8.2 节验证标准
- L1 自动化稳定性测试每周运行（20 篇×5 次）
- L2 人工盲测对照每月运行（5 篇抽样）
- L3 用户体验评估持续收集

## 8. 当前交付切片：创作闭环整合

### 8.1 范围

- 首页承载闭环仪表盘数据，并保留原有问候、输入与创作场景。
- 真实拆文报告提供可选素材沉淀，按剧情、人设、情绪分类，支持文件夹与幂等保存。
- 素材库支持用户新建素材，并在保存后立即进入对应分类。
- 创作工作台的正文、对标文、大纲、细纲、人物小传都具备真实内容来源；AI 可显式引用这些文档和素材库内容。
- 编辑器补齐保存反馈、撤销、重做、标题、列表、清除格式、纯文本粘贴与完成状态。

### 8.2 不可妥协约束

- 拆文素材默认不自动写入，必须由用户明确选择。
- 同一报告的同一候选使用稳定 ID，重复确认不得产生副本。
- AI 只接收用户显式选择的引用，服务端限制引用数量与总字符数，并把引用内容视为资料而非指令。
- 本轮继续使用既有 localStorage／sessionStorage 原型数据层，不引入账号、数据库或跨设备同步。
- 不修改落地页、趋势采集与拆文提示词主体。

### 8.3 验证证据

- `npx tsc --noEmit --incremental false`。
- `npm run build`。
- 浏览器验证首页闭环、素材新建与刷新持久化、工作台文档保存、AI 文档与素材双引用。
- 纯函数验证拆文候选分类与稳定 ID、手动素材工厂、顺序闭环指标、工作台文档播种。

### 8.4 停止条件

- 生产构建或类型检查失败。
- 素材写入未经用户确认，或重复写入产生副本。
- AI 请求携带未选中的文档或素材。
- 用户已有素材、草稿或大纲因本次变更被清空。

## 9. 当前增量切片：例文库

### 9.1 数据边界

- 例文是完整作品，不复用素材条目结构；例文与素材分别存储。
- 例文列表只返回轻量摘要，不批量返回全文和拆文报告。
- 未拆文例文必须保留完整原文，并可从详情页继续发起拆文。
- 已拆文例文必须保留报告编号与分析结果，卡片点击后默认打开 X 光报告原文标签。

### 9.2 展示约束

- 卡片固定展示书名、导语前三句话、题材、标签和拆文状态。
- 导语预览从原文按中文和英文句末符号提取，最多三句，不用字符截断代替句子。
- 已拆文与仅原文必须有明确状态文案和不同去向。

### 9.3 失败与安全

- 例文写入失败时保留用户输入并显示错误。
- 查询不到指定报告时显示明确空状态，不得展示演示报告冒充用户数据。
- 例文接口限制单篇正文长度，防止超大请求占满进程内存。
