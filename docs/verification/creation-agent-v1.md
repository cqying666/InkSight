# 首页创作 Agent V1 验证记录

日期：2026-09-13。对应 PRD：`docs/plan/creation-agent-v1-prd.md`。

## 验证性质

这是工程与冒烟证据，不是人工盲测或发布质量认证。真实模型使用当前配置，仅用自编职场片段；离线合同测试注入确定性模型，不混入真实质量指标。

## 已有证据

- `npm run test:creation`：通过。覆盖用户隔离、输入限额、事务回滚、证据段落与引文、未知方法ID拒绝、工具决策、版本关联、自然语言选定、保存幂等、工作台新建不覆盖、停止后的写入保护、过期运行恢复。
- 知识模块：7份白名单来源 → 231单元（91方法、71框架、69案例）；5组真实语料检索场景通过，另覆盖损坏/缺失索引、来源更新与删除、历史快照。
- SSE：分包、UTF-8、CRLF、末帧、非法JSON与错误传播通过。
- 旧 Pi Agent、教练会话、首页意图合同回归通过。
- TypeScript与隔离目录生产构建通过；构建仍有已有的 Pi 动态依赖、jose Edge API、字体和 Editor hook 警告。

## 真实模型冒烟与修正

输入为自编三段职场片段：女主保留项目账本，主管在会议抢功，女主通过客户邮件还原署名。要求分析人设和信息差，并提出三个职场二创方向，不写婚恋、不依靠男二。

1. 初次失败：模型在一次响应中输出多个JSON动作。严格解析中止，资料保留，页面显示重试。
2. 修正：强化单动作协议，增加全轮最多一次格式纠正，不把多个动作串行直接执行。
3. 发现完成声明问题：模型直接在结束回复列候选，没有持久化方向卡。增加显式交付检查，要求调用directions工具生成可保存成果。
4. 发现自检误判：把二创允许的新角色和因果变化当作“不忠实于原文”。明确允许虚构新增与机制变化，只拒绝硬约束违反、仅换外壳、冒充原文事实。
5. 修正后该会话完成真实拆解、知识检索、三个结构化方向与模型辅助检查。最后一轮6次模型调用，约18秒模型调用耗时；该单样本数据不代表总体延迟或稳定性。

失败均记入记录，不能以最后一次成功声称整体成功率100%。

## 运行边界

- 每会话最多5份资料、累计30000字符；用户消息累计24000字符，最多100条消息。
- 每轮最多8次决策、12次模型调用、180秒；最多一次JSON格式纠正、两次工具失败后停止。
- 当前知识检索为词面召回，不含语义重排；来源版本与引文快照保留。
- 自然语言选定仅对独立且明确的命令执行；复杂含糊表达通过确认按钮完成。
- 工作台衔接为每个已选定版本幂等新建作品，不覆盖已有作品；保存于会话与写入作品分开。
- 没有自动长期偏好记忆、自动投稿和整篇生成。

## 浏览器与 HTTP 验证

- 浏览器完成：首页发送→会话→失败后资料保留→恢复真实拆解与三张方向卡→选定第二个→保存会话成果→工作台新建作品。
- 工作台显示所选方向、人物、冲突、信息差、原始作者限制及来源；未覆盖已有作品。
- 原文依据抽屉可打开，点击第3段引用后跳转并高亮对应段落。
- 窄屏390px检查：文档宽385px，抽屉宽385px，无横向溢出；随后恢复默认视口。
- HTTP：未登录401、超限资料400、不存在会话404；作者模型列表只含id/name/isActive；保存后的会话可读取。
- 测试使用单独临时账户，不使用或修改现有用户密码。测试原始结果保存于Git忽略的数据目录，临时账户在验证后清理。

## 后续质量注意

真实模型仍可能在分析解释中给出超出明示事实的推断；逐字引用验证仅验证引文真实性，不能证明结论被引文充分支持。已经强化拆解与二创分工及知识引用状态说明，仍需人工检查题材适配和建议差异程度。
