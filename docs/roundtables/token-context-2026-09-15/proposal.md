# InkSight 对话 Agent：Token 预算与上下文压缩方案 v0.1

日期：2026-09-15。状态：圆桌评审稿，仅方案，未修改产品代码、运行配置或数据库。角色为 AI 产品经理、AI 全栈工程师、模型评测与可靠性工程师三个独立子 Agent，采用两段标准圆桌：先需求与效果，再交叉审查实现方案。

## 1. 需求背景：解决持续创作中断，而非更换计量单位

InkSight 的四项能力是对标拆解与二创方向、素材转核心梗与框架、写作答疑与审查、小说剧情探讨。会话工作记忆和上下文组织是共同底座。本期讨论限同一会话，不扩展为自动跨会话长期记忆或完整章节生成产品。

核心案例：作者先分析导语的背景、冲突、钩子，再分析第一章大概念，选定早先生成的方向，随后要求比较候选或结合上述分析讨论新故事。应保持作者约束、当前目标和版本，并在必要时找回早期依据。

当前已核实的问题：

- `src/lib/creation/context.ts` 使用 42,000 字符预算，只覆盖公共 context。这个值没有经过模型窗口和真实 Token 分布验证。
- 任务识别的全量目录和历史、规划的 catalog/observed、分析的 paragraphs/knowledge、系统提示词等，还会在 context 外传入。只将字符计数改成 token 计数，仍会漏算。
- 比较按钮只发送“比较这些候选”的泛指消息，没有绑定卡片组版本，可能带入多余候选、报告和长回复。某次执行在 40,077 字符后因无法继续装入讨论记录而失败；这是应用预算失败，不是已证实的厂商上下文溢出。
- 模型层已有 usage 和输出上限，但没有统一的完整请求检查、压缩及重计数流程。现有每轮12次模型调用、8步决策和180秒限制也须纳入迁移；压缩不作为免费额外调用绕过这些保护，是否调整由P0样本决定。

本地活跃配置为 `deepseek-chat`、官方 DeepSeek 域名、`openai-completions`、context_window=32,768、max_tokens=16,384。业务调用规划输出上限为1,800，其余为6,000，运行层再与模型配置取最小值。上述是本地配置事实，不等于已验证的真实模型能力。当前官方模型表列出的型号与该旧别名不同，不能据此推定别名映射或自动扩窗。[DeepSeek 模型文档](https://api-docs.deepseek.com/quick_start/pricing/)

## 2. 目标效果与本次取舍

用户可感知的目标：

1. 正常增长的长会话可以继续，不能因为内部装箱问题要求作者重贴已保存资料。
2. 选定 v1、聚焦 v3、参考旧报告是不同状态；压缩前后都不能混用。
3. 比较按钮准确比较点击时那组版本；修改建议不自动成为已采纳设定。
4. 按问题同时使用导语与章节分析；具体引文可回到原文，不用摘要冒充逐字依据。
5. 超预算前自动重组，失败时保留输入、成果与续做位置；真正缺失的信息才请作者补充。
6. 作者可以查到用了哪些依据、是否经过摘要、哪些范围未覆盖；不要求作者理解 Token 才能使用。

工程目标：所有模型输入输出按 Token 度量，识别、规划、生成、检查、压缩、格式修复、工具结果后的续调及模型切换全覆盖。计数可信等级明确，不把估算包装成精确值。

方案暂以“创作连续性和保真优先”作为待确认设计假设，允许为检索原文或压缩多花必要时间。用户尚未回复偏好问题；这不构成新的费用授权。成本与延迟仍受独立预算控制。

## 3. 先定义三种额度，避免混淆

| 概念 | 作用 | 是否因为压缩而删除 |
|---|---|---|
| 完整会话存储 | 保存原始消息、原文、报告、候选、决定和版本 | 不删除；仍可有独立存储配额 |
| 单次模型请求预算 | 限制一次请求的完整输入及本次输出预留 | 只重组这次交给模型的工作视图 |
| 单轮 Agent 累计用量 | 汇总解决一次用户请求的所有模型调用，控制成本与循环 | 已消耗用量不会因压缩而减少 |

将对话窗口定义为“根据本次模型和任务动态分配的工作窗口”，不定义为整个会话最多保存某个 Token 数。

所有语言内容的模型容量判断使用 Token。上传文件的字节限制、数量限制和数据库存储限制是安全/存储规则，单独显示和说明，不冒充模型上下文预算。现有按字符拒绝消息/资料的规则也需审计，避免新机制上线后仍被旧字符门槛提前拦截。

## 4. 窗口与输出预算如何确定

### 4.1 模型能力档案

每个接入记录：provider、endpoint、请求别名、可获得的实际响应型号/版本、模式、有效窗口 W、独立输入上限 Imax、输出上限 Omax、推理占额规则、tokenizer/协议模板版本、计数方法、依据来源、验证日期和状态。

- W 取已验证服务窗口与管理员产品上限中较小者；如有网关独立限制，也须纳入。
- 32,768 不能因已填在数据库就被认定为验证通过，官方新型号的大窗口也不能自动套给旧别名。
- 首期先完成当前实际服务型号的核验，再冻结数值。新增模型或别名映射变化后重新核验、重计数，旧 Token 缓存失效。
- 未知型号可按有出处的管理员保守档案试运行，并显示“估算”；无可信窗口时不宣称预算保护可用，不盲发大请求。

### 4.2 每次请求的统一放行条件

设 T 为完整输入 Token 数（或带可信等级的估计），R 为本次输出预留，S 为计数/协议误差余量：

**T + R + S ≤ W；同时 T ≤ Imax（若有），R ≤ Omax。**

有效输入上限：**B = min(Imax, W − R − S)**；没有独立输入上限时省略 Imax。

- R 按任务类型设置，并须足够完成该任务。现有1,800/6,000可作为迁移实验起点，不是已经验证的理想值。不能为了塞入更多历史而默默挤掉回答空间。
- 预留的是最大可生成预算，完成后按实际输出 usage 结算；被截断的 JSON/报告不能当完整成果。
- 推理 Token 由模型适配器按厂商规则归入输出预留或独立字段，避免漏算或重复算。
- S 根据计数方式、协议开销及测试误差决定。使用正向误差分位数加保守余量做校准候选；有限样本不能证明未来永不低估。

不推荐拍一个全站固定的32K/64K/128K。当前模型的最终 W、S、R 参数冻结属于实施第一阶段交付，不能拿本次讨论中的例子冒充测量值。

### 4.3 何时压缩、压到多少

- 硬触发：预计 T > B 时，先重组，禁止将已知超限请求发给模型。
- 提前触发：预计 T + G > B 时，可在下一次调用前整理；G 为预计下一步工具返回和流程增长余量，由样本校准。一次性回答可取 G=0。
- 压缩目标为 T_after ≤ B − G；若目标小于任务最小必需内容，改为分步处理，不继续强压。
- 无论是否提前整理，每次真正调用前都重新完整计数。G 不保证未来工具一定返回这么少。

**纯计算示例，不是推荐配置或实际模型上限：**若 W=32,768、R=6,000、S=1,768，则 B=25,000。若下一步预计增长 G=3,000，组织目标为22,000。T=23,000仍可满足本次硬上限，但已超过提前整理目标；T=26,000则必须先重组。例子中的S和G只是为演示算术，上线值必须经校准。

## 5. 全量 Token 计数的边界

统一入口使用同一份规范化请求构造最终 provider 载荷，按其模型可见表达计数；检查后冻结，请求内容不能再被下游偷偷追加。测试应捕获SDK最终发送结构，以覆盖角色模板、协议转换和自动工具描述等开销。

计入：系统提示词、用户输入、选入的历史、作者决定、候选正文、报告、知识片段、模型可见工具描述/schema、工具调用参数和结果、摘要、重试提示、模型可见输出格式描述。当前以JSON动作描述工具，也应计算这些提示词和JSON输入。

不按文本 Token 计入：鉴权header、temperature、超时等传输/控制字段；但若某schema/设置导致服务端注入模型可见提示，相关开销须由匹配计数或误差余量覆盖。

计数路径按可信度选择：

1. 匹配厂商、型号和输入形式的计数接口；接口若声明是estimate，仍标估算。
2. 匹配当前型号的 tokenizer 加协议模板；仅裸字符串tokenizer并不能证明完整请求精确。
3. 未知兼容模型采用经过样本校准的 Token 估算，并保留方法标签和安全余量；不得把统一字符系数当精确计数。

DeepSeek 官方提供离线 tokenizer 示例，并以API返回 usage作为实际用量依据；示例包是否匹配正在使用的别名需要验证。[DeepSeek Token 说明](https://api-docs.deepseek.com/quick_start/token_usage/)

计数接口也可能与实际输入有小差异；应保存 estimate、方法版本、usage实际值和误差，而不是声称预计算绝对准确。[Claude 计数说明](https://platform.claude.com/docs/en/build-with-claude/token-counting)

最终完整请求总数是放行依据；各组件token归因可用于解释，但简单相加独立字符串的计数不一定等于完整模板计数。

输出和费用日志：每次调用记录实际输入、实际输出、缓存读写、推理子项及耗时；按厂商规则规范化为总量，缓存/推理如已包含于总字段不能再次相加。缓存降低费用不等于不占窗口。[上下文与缓存规则示例](https://platform.claude.com/docs/en/build-with-claude/context-windows)

流式取消、网络失败或 usage 缺失时标记 unknown/estimated，不写成0消耗。规划、压缩和格式重试均计入单轮累计用量；累计成本额度耗尽应保存进度，不能靠继续压缩“清零”。

## 6. 重组与压缩流程

**绑定本轮任务与版本 → 构造最小必要上下文 → 完整计数 → 超限则逐级重组 → 校验 → 重计数 → 发送 → usage校准。**

### 第一级：确定性减量，优先不调用模型

- 比较候选时传点击卡片组的具体ID和版本，不能让“这些候选”扩大为全部历史版本。
- 报告、候选和原文只保留一份模型可见正文；其余位置改为引用，清除context与独立参数的重复。
- 移除与本次目标无关的资料、重复工具日志和已被替代的解释。原件仍留在会话存储。
- catalog分层检索或分页，不把完整目录和全历史作为第一次任务识别的必需载荷。最近尚未识别的新原文也要先按段落定位处理，不能先把超大正文塞入路由调用。
- 读取和检索工具支持按Token限制返回范围及分页；每次返回后重新计算下一请求。

### 第二级：按任务摘取，保持依据可回查

以来源ID、版本和段落定位选取支持当前问题的发现及原文证据。比较方向以候选的关系、动力、选择、风险为主；只有需要解释迁移依据时再取相应分析，不默认装入四份全文报告。

选定和聚焦身份都保留；实际比较/创作对象单独绑定。旁路候选可保留名称与状态索引，不因当前聚焦就强制加载全部正文。

### 第三级：模型生成结构化派生摘要

保留原始会话，只新建派生摘要。至少包含：来源ID/哈希/版本、覆盖区间、当前任务摘要、事实与解释、有效决定引用、被替代决定引用、未确认建议、未解决问题、重要因果关系、可回取位置、生成模型/提示词版本、输入输出Token。

硬保护：当前目标及必要指令、对象身份/版本/状态、作者有效硬约束与确认来源、关键否定条件和所需逐字引文。硬保护内容不由摘要模型重新解释后覆盖原件。候选动机和因果也是任务语义，不能只留ID就算保真。

“完整作者历史”不再每次强制原样注入：相关明确决定从权威记录带入，其他历史按任务摘要和回查。未登记的旧约束先溯源补齐，不能直接扔掉。

摘要不得把小说台词变成作者指令，也不能提升检索资料的权限。压缩后的“建议”仍是建议，原文未知仍是未知。

### 压缩调用自身的预算

- 压缩器同样经过完整计数和输出预留；不能把已经超限的上下文整体交给同一模型压缩。
- 先按已保存原文切分可容纳的块，再生成块摘要并汇总；必要的跨块实体、时间和因果连接需保留。
- 超大任务按块记录覆盖进度；未读完不能声称全文结论。
- 摘要可缓存，键包含来源版本、任务范围、摘要策略及模型/tokenizer版本；相关内容变化时失效。
- 多次压缩优先从原始记录和权威决定重新派生，避免无限“摘要的摘要”；摘要可回退，不能覆盖原件。

### 校验、终止与降级

1. 确定性检查：对象ID、版本、权限、有效决定、引用位置与覆盖范围。
2. 语义检查：人物动机、因果、否定条件、确认状态有无变化；自动检查只做辅助，评测需人工判断。
3. 重计数：只有达到放行条件且校验通过才替换本轮工作视图。
4. 首期建议一次原请求最多两轮重组修复；分块任务另受累计调用/Token/耗时限额。两轮是防循环的待评审默认值，不是行业标准。
5. 无净节省、摘要无效或预算耗尽：保留旧视图、原始数据和进度；改为分块或交付明确标注的已完成部分。
6. 若连不可缺少的材料与最小输出都无法容纳，要求缩小分析目标或选择已支持的大窗口模型；不要求用户重新上传已有资料，不自动切换模型产生额外费用。

## 7. 程序与系统提示词各负责什么

| 责任 | 程序必须保证 | 模型/系统提示词负责 |
|---|---|---|
| Token预算 | 能力档案、计数、预留、发送前门禁、日志 | 不自报精确Token，不决定突破硬上限 |
| 相关内容 | 权限、版本、快照和引用有效 | 按本轮问题选择必要资料，说明依赖 |
| 压缩 | 分块、调用限额、结构校验、回退、重计数 | 忠实归纳，保留因果、否定、未知与确认状态 |
| 失败恢复 | 原件保留、停止隔离、检查点、幂等 | 说明覆盖变化，不伪装完成 |

需新增/修订的提示词契约：任务选择器不得默认拉全库；摘要器只输出派生摘要且逐项绑定来源；回答器区分原件与摘要并在需要原文时回查；校验器检查状态、否定条件和因果。预算数值由程序传入，不能只写“请注意上下文长度”期待模型自行解决。

## 8. 页面行为与比较按钮专项

- 点击后立即显示“正在比较这3个方向”，并定位至最新执行位置；按钮组状态与请求绑定，防止重复提交。
- 发送明确候选ID与版本快照；只有一个候选的卡片组不显示“比较多个候选”，同方向版本比较应明确标明。
- 自动整理期间显示“正在整理较早的讨论，保留你的设定与约束”；完成后可展开摘要覆盖和来源，不强制弹窗确认。
- 正常内容选择无需每次解释被省略的无关历史；范围真正缩小则明确列出已读/未读部分。
- 失败提示同时出现在按钮附近和最新执行状态，提供继续/重试；重试不重复写入已完成成果。
- 作者界面主要展示任务与依据。管理员/调试视图显示模型档案、预算、计数等级、压缩前后Token、输出预留与实际用量。
