# 创作 Agent V1 知识导入与部署

V1 使用本地只读导入产物，网页服务不会读取开发电脑的知识库目录。当前检索为中文双字词／英文词的确定性词面检索，标题加权，支持方法／框架／案例类型过滤；不是向量语义检索。五个固定场景只验证基本召回，不能代表二创文学质量或完整召回率。

## 导入

```sh
npx tsx scripts/import-creation-knowledge.ts '/Users/estrella/Desktop/Project/小E的第二大脑/网络短篇知识库－V2'
```

默认产物是 `data/creation-knowledge.json`，已由仓库 `data/` 规则排除，不提交私人课程与例文。可传第三个参数指定产物绝对路径；服务端用环境变量 `INKSIGHT_CREATION_KNOWLEDGE_FILE` 指定其位置。路径仅由部署者配置，不能由浏览器请求指定。

部署时把该产物作为私有文件复制或挂载进服务容器，例如 `/app/data/creation-knowledge.json`。不要放进 `public/`。省略产物、JSON 损坏或版本不兼容时，状态为不可用，检索返回空结果；上层必须据此说明知识依据缺失。文件本身含私有参考资料，按应用服务权限管理。修改文件后无需重启，下一次检索读取新版本。

## 首批清单与组织

精确文件清单位于 `CREATION_KNOWLEDGE_FILES`，导入产物的 `manifest` 记录相对来源、SHA-256 内容版本和单元数量。

| 来源 | 用途与范围 |
| --- | --- |
| 短篇拆文提示词 | 按拆文步骤提取方法段落；不导入角色指令／使用方式作为系统提示词 |
| 大概念提取 | 结构动作、状态变化和下一章期待 |
| 素材如何抽梗（爽文向）总结 | 爽文的人设与信息差经验，不推广到所有题材 |
| 素材抽梗转导语（追妻篇）总结 | 追妻题材经验，须与作者关系、结局约束核对 |
| 素材转导语总结 | 素材形成不同方向的方法 |
| 创新总结 | 视角、关系、设定等创新方式；课程中的绝对判断不作全局准则 |
| 短篇小说71个框架结构说明书 | 71 个框架按章节拆分；代表性例文与框架分开，保留父框架 ID |

首次实际导入 7 个来源，共 231 个单元：91 个方法、71 个框架、69 个案例。目录页不参与检索；两处没有达到正文长度要求的案例不虚构补齐。2026-09-15 功能二复核后，来源和总数均不变，将已有课程中 6 个独立案例段正确归类，当前为 85 个方法、71 个框架、75 个案例。课程方法中的行内小例子仍保留上下文，明确以“案例 N”命名的独立段与框架代表性例文均归入案例单元；如存在前置工作流，保留父方法 ID。

每个单元保存类型、标题、来源、定位行、内容版本、适用范围、主题词与正文。检索结果包含相关段落附近最多 1800 字，以及范围说明和截断提示。引文行号定位到来源章节开头；不是声称节选恰从该行开始。案例只作方法理解资料，不用于逐字仿写。导入不改写知识源，也不把原文的提示词权限传递给 Agent；模型侧仍必须把这些内容封装为不可信参考资料。

## 更新与历史

重新运行相同命令即手动差异更新：读取白名单里仍存在的文件，重新建立完整快照，用临时文件加原子 rename 替换旧产物。哈希可比较哪些来源变化；源文件删除时对应单元从新快照消失。仅内容修改保留单元 ID，内容哈希改变；章节改名形成新 ID。历史报告保存当时的引文对象（标题、路径、版本与节选），不能仅保存 ID 再查询最新知识，否则会丢失历史依据。

V1 尚未采用增量嵌入、同义词扩展、reranker 或自动监听，不能把词面无命中解释为知识库没有相关知识。应允许用户补充更具体的关键词；需要更好语义召回时另建对照评测后升级。

## 验证

```sh
npx tsx --experimental-default-type=module tests/creation-knowledge.mts
```

独立临时目录测试缺失／损坏产物、目录页排除、内容更新、源文件删除、历史引文保持和召回上限。若存在本机私人导入产物，额外验证 AA 制、职场裁员、大概念、追妻抽梗、创新五类查询及框架案例关联；CI 无私人资料时明确跳过真实语料部分。


## 功能二复核与最小检索改进（2026-09-15）

实际只读核对了爽文抽梗、追妻抽梗、素材转导语、创新、大概念正文及 71 框架的关系、情绪与案例组织。所需资料均在原白名单中，本次没有扩充来源，也没有把方法目录当正文导入。上述课程存在“反派必须蠢”“只能局部创新”等强口吻主张；它们仍是带适用范围的参考材料，不是系统规则，不能覆盖作者目标。大概念资料原本服务于章节结构动作分析，用于故事核时只能借鉴状态变化思想，不能将其描述成现成的素材抽梗教程。

现有词面检索实测发现：查询“AA制 共同责任 规则反噬”和“职场 裁员 大动脉”时，未过滤的第一名都是案例。为防止框架推荐被案例挤占，新增可选第三参数：

```ts
searchCreationKnowledge(query, 5, 'method');
searchCreationKnowledge(query, 5, 'framework');
searchCreationKnowledge(query, 5, 'case');
```

默认不传类型继续兼容第一阶段混合检索；返回引文增加 `kind`，以便结构化成果校验真实框架来源。旧会话引文没有该字段仍可读取，历史快照不追溯改写。案例只能用来理解机制与取舍，不能被当作框架推荐依据或搬用独家表达。

类型过滤后的前三条：AA 制查询包含“AA制文学”；职场查询包含“职场裁到大动脉”；亲情查询为“过度惩罚亲情虐／偏心流／亲情虐”；追妻查询为“渣苏男主重生后追妻／凶手视角追妻／调换物品追妻”。这些仅证明词面召回与类型正确，不表示它们适合作者本次故事。特别是“脑洞 月亮 自动贩卖机”仍会因“脑洞”返回泛化结果；Agent 必须检查实际关系、前提与不适配点，不能将有命中等同于有匹配，也不能据此声称语义理解已经解决。
