# 会话工作记忆与上下文组织：实现说明

日期：2026-09-14。对应 V1 PRD 的 FR-02、FR-03、FR-06；四项能力共用，不增加第五项业务能力。

## 目标与范围

在同一会话内，根据当前目标组合作者要求、选定/聚焦版本、相关分析及前序讨论。特别支持：导语分析 → 第一章分析 → 选定早期二创方向 → 综合追问。暂不建设跨会话自动长期记忆或完整单章规划产品。

## 工作方式

1. 会话保存全部来源、报告与方向版本；将历史未结构化助手答复登记为可查的讨论记录，状态默认为建议。
2. 任务识别收到完整会话索引，包括报告标题、覆盖范围、发现标题、方向状态、作者决定、讨论记录摘要。按问题选择对象 ID，不按最近三份报告过滤。
3. 执行器校验 ID 属于当前会话；始终保留选定版本和聚焦版本，并明确区别。选定版本的原始关联报告作为来源保留，后续相关报告同时进入上下文。
4. 作者明确决定使用逐字用户要求、消息 ID 和方向家族记录；新决定可明确替代旧决定。没有用户采纳依据的助手建议保持 proposal。
5. 每次规划、分析、方向修改及检查调用都经过统一上下文构建器。需要更多资料时，模型可调用 load_context；读取正文仍使用 read_source。
6. 完成答复后记录实际提供给工具的上下文清单和本轮讨论索引；消息、报告和新方向保留当时依据。刷新后可恢复，后续讨论按相关性读取。

## 信息身份

- 对标原文和报告：参考事实/分析，不能直接成为二创故事事实。
- selected：作者已选定的创作基础；明确待补项仍待补。
- focused：当前正在讨论的版本，可能尚未选定；讨论切换不替换 selected。
- candidate/historical：未采纳/历史版本；不得静默成为正式设定。
- 作者决定：active / superseded，带来源消息和方向范围；全会话硬约束另行明确传入。
- 讨论建议：proposal；只有明确作者采纳记录才在对应方向上下文中标为 accepted_by_author。

## 执行和展示

`src/lib/creation/context.ts` 提供索引、选择校验、作者决定更新、统一上下文构建及讨论记忆更新；不执行跨会话检索。

`task.ts` 在现有任务识别调用中同时选择相关报告和讨论对象，不额外增加独立记忆模型调用。`agent.ts` 对执行模型统一注入 context，并保留按需补充动作。

回复下方可展开“本轮上下文”，查看本轮目标、选定/聚焦版本、报告及作者决定；该清单说明提供给了模型哪些信息，不宣称每条都实际影响最终答案。

## 预算与安全

统一上下文主体使用 42000 字符预算，不等同于模型 token 上限。当前选定/聚焦版本、作者决定和保留的作者历史要求优先保留；相关报告或讨论记录超出预算时记录缺项，并停止生成，明确要求缩小范围。不会静默截断来源正文。

该预算只覆盖统一 context，独立工具参数、检索返回值及 catalog 仍受现有会话/资料/工具上限约束；进一步整体 token 预算调度是后续优化项。

用户消息里的已登记正文会替换为资料引用，原文台词不能被逐字决定校验当作作者要求。语义上是否构成明确要求和是否应采纳，仍依赖任务模型识别；不宣称靠 ID 校验即可证明全部语义正确。

## 验收

- 多份无关新报告不能挤掉当前需要的早期报告。
- 15 个候选下仍准确保留早期选定版本。
- 方向调整模型及检查模型都获得导语和后续章节报告。
- 当前方向的专属决定不迁移到另一个方向；旧决定明确标为被替代。
- 模型建议不自动确认；作者采纳可追溯。
- 仅讨论、不生成方向的请求正常交付，不被旧关键词完成检查阻塞。
- 超预算、无权限或不存在的引用不伪装成正常完整上下文。

验证结果与实际浏览器证据见 `docs/verification/creation-memory.md`。
