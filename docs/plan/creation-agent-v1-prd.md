# InkSight 首页创作 Agent V1 PRD

> 版本：0.1（需求收束稿）  
> 日期：2026-09-13  
> 状态：根据当前讨论整理，作为产品评审与开发拆解入口；不代表功能已实现，也不代表已授权整个平台重构。  
> 上位共识：[创作 Agent 产品共识](./creation-agent-product-consensus.md)

## 1. 背景与目标

InkSight 将首页大输入框升级为创作 Agent 入口。当前首页具备文字输入、文件解析、模型选择和固定技能选择，但提交后主要执行固定功能或跳转页面，尚不能在首页发起的同一会话中完成连续创作协作。

V1 聚焦一条完整链路：

**上传或粘贴对标文 → 明确目标与约束 → 有依据地拆解 → 提出有实质变化的二创方向 → 连续追问与调整 → 选定并保存方向。**

产品目标：

- 帮助网络短篇作者理解对标文的创作机制，并把分析转化为可继续创作的新方向。
- 避免用户在拆文页、聊天入口和工作台之间反复复制资料。
- 为后续四类创作能力建立可复用的会话、上下文、工具调用和结果管理基础。
- 为 AI 产品经理求职展示积累真实、可检查的产品设计、知识检索、人机协作和评测证据；不将接入框架或生成字数当作业务收益。

## 2. 四类能力与版本定位

| 建设顺序 | 能力 | V1 边界 |
|---|---|---|
| 1 | 对标文拆解与二创方向 | 本版主能力，做通拆解、方向生成、追问、选定与保存 |
| 2 | 素材转核心梗与框架 | 后续版本；本版相关知识仅用于支持对标文二创 |
| 3 | 写作答疑与审查 | 本版可回答当前拆文和方向相关问题；系统化导语、大纲、细纲、全文审查后续建设 |
| 4 | 小说剧情探讨 | 本版支持围绕当前候选方向的有限讨论；跨章节、长期作品状态下的深度分支推演后续建设 |

优先做对标拆解的依据：已有拆文和导语分析能力可复用，知识库已有直接相关方法，原文证据与新方向差异较容易检查，能够较快形成可演示的完整闭环。

基础多轮对话从 V1 开始支持，不因“小说剧情探讨”排在后续而延后。

## 3. 目标用户与核心场景

目标用户：有对标短篇或导语，希望理解写法、探索新故事方向，并通过反馈逐步明确创作方案的作者。

### 3.1 代表性需求

> “拆一下这篇的女主人设和信息差，给我三个职场方向，不要再写婚恋。”

后续追问：

> “第二个方向反派太脸谱化，保留女主的主动性，不要靠男二解决问题。”

最终操作：

> “就选调整后的第二个，保存下来。”

### 3.2 用户需要解决的问题

- 不知道应该选择哪个功能按钮才能表达真实需求。
- 拆解只有剧情复述，缺少机制解释与原文依据。
- 二创只换姓名、职业或场景，缺少实质变化。
- 追问时资料、约束或候选版本丢失。
- 讨论中的可能性与正式选定方向混在一起。

## 4. V1 范围

### 4.1 必须交付

1. 首页发起会话，以及连续追问和历史恢复。
2. 目标、分析对象、范围、约束及必要信息缺口的识别。
3. 文件与文本资料管理，无作品也可开始会话。
4. 按目标读取资料、检索知识、调用拆文能力、检查结果的有限 Agent 闭环。
5. 对标文拆解、原文依据与知识依据展示。
6. 二创方向生成、比较、调整、选定和保存。
7. 首批四类知识资料导入、检索和来源追溯。
8. 执行进展、停止、失败、重试和刷新后的真实状态展示。
9. 最小评测样本集、执行记录与失败案例记录。

### 4.2 本版不包含

- 从任意现实素材出发的完整抽梗与框架推荐产品流程。
- 自动生成完整小说、自动投稿。
- 系统化全文审稿与跨章节长期剧情推演。
- 自动提取作者长期偏好、完整长期记忆管理。
- 完整知识库管理后台、自动目录监听同步。
- 整个平台重构或所有旧功能的会话化迁移。

## 5. 核心交互流程

1. 用户在首页输入要求，上传或粘贴对标文本，可选择任务提示和模型。
2. 发送后进入创作会话页，原始要求与资料完整带入，不要求重复上传。
3. Agent 判断目标、文本类型、分析范围与硬约束；缺少必要信息时在会话中询问。
4. Agent 按需读取文本、调用分析能力和检索方法；界面显示实际执行进展。
5. 会话展示重点结论，详细拆解、原文和知识依据按需打开。
6. 用户要求二创时，生成方向候选；只要求拆解时，交付拆解即可，提供继续探索入口。
7. 用户聚焦某方向、比较候选或自由追问，系统保留约束并生成新版本。
8. 用户明确选定方向；保存时明确目标，可先保存为会话成果，再按需要关联作品。
9. 用户主动进入工作台时，带入已确认成果及其来源关联。

简单问题可直接回答，不强制展示计划，也不要求每轮重新拆全文或检索全库。

## 6. 功能需求

### FR-01 首页输入与入口

- 保留现有上传、文件解析和模型选择能力。
- 输入框提示语应说明可上传对标文，并描述希望分析或变化的方向。
- 提供“拆解对标文”“拆解并探索二创方向”等任务提示；它们帮助表达需求，不限制自由输入。
- 旧“写导语、大纲生成、细纲生成”等入口保持可达，并与新会话任务分组，避免暗示已全部支持连续协作。
- 上传文件本身不等于用户要求全文拆文；文本长度不能独自决定它是导语还是大纲。

### FR-02 会话与上下文

- 支持未关联作品的新会话，后续可关联作品。
- 保存消息、资料引用、目标、约束、工具结果摘要和方向版本。
- 显示当前使用的文件与关联作品；多份资料用途不明时应澄清分析对象。
- 用户明确提出的结局、题材、人物行动限制等作为显式约束读取，不能依赖向量召回。
- 提供历史会话入口，刷新或离开后可恢复已保存内容。
- 不自动将“最近一次拆文”作为当前作品事实；跨会话资料需有明确关联。

### FR-03 有限 Agent 决策与执行

- 根据目标选择直接回答、读取资料、检索方法、调用分析或询问信息。
- 工具执行后检查范围、结果完整性与约束符合情况，再决定补充、交付或停止。
- 已有稳定分析流程封装为可调用能力，外层负责目标判断和后续动作。
- 用户只要求人设等局部分析时，必须有实际可调用的对应能力；暂不支持时明确说明，不能以完整拆文冒充按需执行。
- 设置调用次数、重试、耗时与成本预算；具体数值开发前确定。
- 工具或检索失败不得伪装成功。降级回答必须说明依据和覆盖范围的变化。

### FR-04 对标拆解

- 支持导语专项分析，以及在已验证长度范围内的短篇分析。
- 根据目标覆盖剧情、人设、信息差、情绪推进、大概念等相关维度，不强制每次输出全部栏目。
- 区分“发生了什么”和“为何这样安排、带来什么状态变化”。
- 对原文事实和关键分析提供可定位的文本依据；解释性判断与原文事实区分呈现。
- 用户仅提供导语或部分章节时，不推断成已经阅读全文；缺失结局等标记为未知或待补。
- 长度上限、长文分段方式及覆盖规则需验证后确定；超限必须提示，不得静默截断后声称完成全文分析。

### FR-05 二创方向

- 基于拆解出的可迁移机制生成多个候选；建议默认三个，作为待评审的产品默认值。
- 每个候选包含：方向名称、故事核、人物关系、冲突与信息差、情绪落点、可迁移机制、实质变化、待补设定和风险。
- 区分原文事实与新加入的虚构设定。
- 新方向需改变故事的关键关系、冲突动力、人物选择或因果推进，不能仅替换姓名与职业。
- 框架推荐说明适配条件、理由和局限，允许没有合适框架，不机械套用模板。
- 不宣称能保证原创性、过稿或爆款；差异检查围绕可观察的情节、关系和表达展开。

### FR-06 追问与版本

- 支持“讨论第二个”“比较第一和第三个”“保留信息差但换关系”等自然语言反馈。
- 明确当前聚焦方向；调整产生新版本，保留被替换的版本供查看。
- 新反馈与已有硬约束冲突时，确认是否更新约束，不静默覆盖。
- 讨论、选定和保存是不同状态：聚焦不等于选定，选定不等于写入作品。
- 后续建议不能将未采纳或已废弃方案作为正式设定。

### FR-07 选定与保存

- 支持通过按钮或无歧义的自然语言选定具体方向版本。
- 保存成果包括方向内容、版本、关键约束及关联拆解来源。
- 无关联作品时可保存为会话成果；写入作品前明确目标作品。
- 用户明确要求保存且对象清楚时直接执行；目标不明或涉及覆盖既有内容时再询问。
- 写入失败显示失败状态，保留候选内容以供重试，不能显示“已保存”。
- 进入工作台需由用户主动触发，并带入已确认成果，避免再次复制。

## 7. 前端设计要求

### 7.1 页面结构

采用“首页起聊，会话页承接”的方案，复用现有品牌、配色与输入框风格，不重做整个首页。

| 区域 | 内容 |
|---|---|
| 首页 | 保留品牌与现有概览，调整输入提示、任务入口和发送行为，增加历史会话入口 |
| 会话顶部 | 会话名称、关联作品或未关联状态、当前资料 |
| 会话主区 | 消息、执行进展、重点结论、二创方向卡片 |
| 底部输入区 | 固定追问输入框，支持补文件与模型选择 |
| 按需详情区 | 完整拆解、原文定位、知识依据和方向详情 |

详情区桌面端可使用侧栏，默认不常驻；窄屏使用抽屉或详情页。具体尺寸与视觉稿后续确定。

### 7.2 结果组件

| 组件 | 必要信息与操作 |
|---|---|
| 拆解摘要 | 重点结论、覆盖范围、查看完整拆解 |
| 原文依据 | 文件名称、段落或章节定位、引用片段 |
| 方法依据 | 知识条目名称、适用说明、支持的判断；不能只罗列无关来源 |
| 方向卡片 | 故事核、迁移机制、变化、待解决问题；讨论、比较、选定 |
| 已选定成果 | 选定版本、保存状态、关联目标、进入工作台 |

详细报告避免全部塞入一条长回复。用户始终可自由输入，不受卡片按钮限制。

### 7.3 执行与异常状态

状态至少包括：等待补充、执行中、完成、部分完成、失败、已停止。

- 进展文案对应真实动作，例如读取文本、分析关系、检索方法、检查约束。
- 不以虚构的进度百分比或步骤制造执行感，不展示内部推理过程。
- 停止后不再发起新步骤，尽可能取消正在执行的请求，并保留已完成内容。
- 重试针对失败步骤，防止重复保存或无必要地重新执行全部流程。
- 刷新后展示实际任务状态；不承诺本版自动恢复所有中断调用。

### 8.1 导入与使用原则

- 首批精确文件清单在导入时形成清单记录，不把整个课程目录无筛选导入。
- 解析 Markdown，保留来源、章节、版本或内容哈希、题材、任务、适用条件和限制。
- 按方法、框架和案例组织知识单元；拆分后仍保留上下文与关联。
- 71 个框架主要提供关系、导语机制和案例参考，不能直接等同于 71 套完整章节大纲。
- 教学提示词整理为受控方法模板；检索文本作为资料，不能改变 Agent 权限和执行规则。
- 保留题材限制，例如爽文夸张反派的方法不能成为全部题材的统一标准。
- 目录说明不算独立方法正文；文档标注 verified 不等于产品效果已验证。
- 方法知识与用户作品资料分开管理；检索和读写必须限定用户及作品权限。

### 8.2 更新机制

V1 支持手动导入和差异更新，无需管理后台或自动监听。更新时处理旧索引、删除条目和失效引用；历史成果保留当时使用的来源版本信息。

仅访问本地路径不等于已接入产品。部署环境通过导入产物使用知识，不假定网页服务始终能读取开发电脑目录。

## 9. 最小数据对象

以下为产品层对象要求，不指定数据库结构。

| 对象 | 最小信息 |
|---|---|
| 会话 | 所属用户、可选作品、消息、当前目标、约束、资料关联 |
| 原文资料 | 文件名、正文、版本、段落定位与所属范围 |
| 执行记录 | 任务状态、真实工具动作、结果、错误、耗时及可获得的用量 |
| 拆解成果 | 分析范围、结论、原文证据、方法依据 |
| 方向版本 | 候选标识、版本、父版本、内容、反馈、聚焦与选定状态 |
| 保存成果 | 选定版本、保存目标、保存时间、来源关联 |
| 知识单元 | 类型、来源、版本、适用范围、正文与关联案例 |

作品正式设定、任务约束、知识资料和讨论候选分开存储或明确区分，不依靠单一聊天文本承担所有状态。

## 10. 验收标准

以下为应验收的行为，不是已实现声明。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-01 | 首页上传并发送 | 进入会话，指令与资料完整保留，无需再次上传 |
| AC-02 | 只提供文件未说明任务 | 不直接认定为全文拆文；结合会话判断或询问 |
| AC-03 | 要求只分析人设 | 执行实际支持的局部能力，或明确能力缺口，不静默扩大任务 |
| AC-04 | 仅提供导语 | 明确分析范围，不编造后续章节、结局或已读全文状态 |
| AC-05 | 查看拆解依据 | 关键原文判断可定位，引用确实存在；解释性判断与事实区分 |
| AC-06 | 查看知识依据 | 方法引用与结论相关，保留来源及版本；无支持时不编造引用 |
| AC-07 | 请求二创 | 候选有可解释的实质差异，新增设定与原文事实分开 |
| AC-08 | 连续调整方向 | 聚焦对象和版本明确，硬约束保留，废弃候选不成为正式设定 |
| AC-09 | 选定并保存 | 保存具体版本至明确目标；恢复会话后内容与保存状态一致 |
| AC-10 | 停止、失败、重试 | 显示真实状态，保留已有结果，不重复写入成果 |
| AC-11 | 刷新与历史恢复 | 找回已保存会话、资料与候选；未完成任务不假装完成 |
| AC-12 | 跨用户或跨作品读取 | 无权限资料不可访问，未关联作品资料不自动混入上下文 |
| AC-13 | 知识更新 | 新检索使用有效版本，旧成果的历史依据仍可识别 |
| AC-14 | 工作台衔接 | 主动打开工作台后可获得已确认成果，不需复制全文 |

## 11. 评测与展示证据

- 建立覆盖导语、完整短篇、局部分析、缺失资料、硬约束、多轮反馈、失败和超限的固定样本。
- 保留未参与提示词调优的验证样本，失败样本计入成功率。
- 对照同一模型直接回答与知识检索、工具增强后的结果；条件允许时进一步区分固定流程与有限自主决策的收益。
- 人工评价原文依据真实性、机制抽象质量、二创实质差异、约束保持和建议可执行性。
- 记录任务完成情况、方向选定与保存情况、返工轮次、耗时、调用用量和可计算成本。
- 不把点击选定等同于文学质量提升；用户收益需要结合实际反馈判断。
- 样本规模、人工评分规则、最低通过标准和延迟预算在开发拆解前确定，不引用旧单次运行报告作为稳定性结论。

演示至少保留一条真实成功链路和一个真实失败或调整案例，可展示资料、调用动作、引用、作者反馈和最终版本。

## 12. 建议实施拆分

| 阶段 | 交付 | 完成标志 |
|---|---|---|
| A：最小会话链路 | 首页起聊、会话页、资料和约束保存、已有拆解能力接入 | 上传后能得到结果并继续追问，刷新可恢复 |
| B：知识与依据 | 首批资料整理导入、按需检索、原文及方法引用 | 结果依据可查，范围和缺失信息可见 |
| C：二创闭环 | 方向生成、比较、版本调整、选定保存、工作台衔接 | 完整走通本版核心链路 |
| D：发布前验证 | 异常、权限、超限、知识更新及质量对照验证 | 核心验收通过，质量门槛达到约定标准 |

以上是同一 V1 的交付拆分，不是四项业务能力的重新排序；没有承诺具体工期。
