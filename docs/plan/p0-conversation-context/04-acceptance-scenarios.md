# P0-04 验收场景与执行口径

状态：场景设计已交付，产品功能测试待P1/P2/P3执行。P0的模型探测和离线计数证据另见evidence，不能把它们当作这些业务场景已通过。

## 1. P0本身怎样验收

用户检查四件事：

1. 是否同意取消比较按钮、通过自然语言表达选择/比较/版本回退，轻量反馈且仅真歧义澄清？
2. 是否同意原始会话保留、保护作者要求/状态/版本/必要引文，优先去重摘取再摘要？
3. 是否接受模型事实、估计、参数建议的区分，以及49,152 Token工作窗口作为后续试行候选？
4. 以下场景是否足以覆盖最关心的创作流程？

用户验收通过后仍需明确下令P1；P0交付不自动触发实施。

## 2. 共同测试夹具

候选组A：A1寿宴、A2职场、A3婚礼，各v1。后续A1形成v2/v3，已选A1v1、聚焦A1v3。候选组B另有B1/B2/B3。资料含导语报告G、第一章报告C、无关科幻报告X。明确限制为“女主主动，不靠男二”，旧“不复合”可由作者明确撤销。模型曾建议取证和搬家，作者尚未采纳。

所有案例保存用户输入、前置状态、实际绑定对象、输入上下文、结果和运行日志。不以回复里一句“我记住了”代替状态核验。

## 4. 12个预算与故障用例

使用P0建议窗口49,152、内容输出预留6,000、S=1,024时，B=42,128；以下用例以准确构造/计数的输入为准，不用字符数代替。

| ID | 输入/故障 | 通过条件 |
|---|---|---|
| F01 | T=42,128，恰好满足硬上限 | 允许；保留全部输出预算 |
| F02 | T=42,129，仅超1 Token | 发送前阻止并重组，不盲发 |
| F03 | T=39,000，下一步预计增长4,096 | 高于软组织目标时可先整理；未把软阈值当模型报错 |
| F04 | 系统提示与必需约束本身就超限 | 明确无法容纳，保留原件，不能截掉约束伪装成功 |
| F05 | 切换型号/别名响应发生变化 | 计数/能力档案重新校验，不沿用旧缓存 |
| F06 | tokenizer缺失或只有未知估算 | 明示计数等级，不伪称精确；缺可信窗口则不发大请求 |
| F07 | 压缩输入自身超限 | 先分块，压缩请求也过门禁 |
| F08 | 摘要改变“不靠男二”或把v3当已选 | 校验失败不提交，回退原件 |
| F09 | 两轮重组无净收益/额度耗尽 | 有界停止与续做，不无限重试 |
| F10 | 输出finish_reason=length或JSON截断 | 结果不当作完整报告保存，保留已完成部分 |
| F11 | 流式断开、usage缺失、取消 | 消耗标未知/估算，不填0当实际；无晚到写入 |
| F12 | provider仍拒绝窗口、缓存/推理统计重叠 | 有界恢复并更新误差观察；不重复计算已包含于总量的子项 |

## 5. 验收指标与证据

硬门槛建议：测试集中版本混用、硬约束遗漏、建议转事实、伪造引文、已知超限发送为0；不存在未授权写入或删除原件。

质量建议：12组配对由两位评审盲评任务完成度、人物动机、因果完整性和建议可执行性，至少11组不退化且无严重退化，分歧复核。属于首期建议，不是行业标准、线上零故障保证或已通过统计。

工程日志需包含：模型档案版本、计数方法、完整输入估计、输出预留、实际usage、压缩前后Token、被移出工作视图但可回查的来源、覆盖范围、累计用量、耗时、停止原因和恢复位置。组件归因和总数分开。

P3必须在用户实际使用的3107页面验证，不以其他端口HTTP200代替端到端验收。
