# P0-02 上下文保留与压缩优先级

状态：待用户验收；适用于四项能力的当前会话公共底座。

## 1. 定义

压缩只生成“本轮模型使用的派生工作视图”，不删除原始消息、原文、报告、候选和决定记录。存储容量与模型窗口分开。输出变短不等于语义保持，ID正确也不等于人物动机正确。

## 2. 信息处理优先级

| 等级 | 内容 | 本轮处理 | 不允许的变化 |
|---|---|---|---|
| A 必须保护 | 最新真实要求；本轮对象和版本；selected/focused区别；有效作者约束及采纳/撤销关系；任务所需逐字引文 | 保留权威内容及来源；不通过自由摘要覆盖 | 否定丢失、版本混淆、建议变事实、超出范围的事实 |
| B 按任务必需 | 指定候选的故事核、关系、动机、因果；直接相关分析结论及证据 | 按问题选取，保留必要语义和回查位置；必要时分段 | 只留候选ID就丢掉关键人物选择 |
| C 可压缩 | 早期讨论、重复解释、已完成工具结果 | 可生成结构化摘要，带版本、范围、状态和未决问题 | 把尚未采纳的建议写成正式设定 |
| D 可不带入 | 无关旧任务、无关候选全文、重复报告副本、重复状态日志 | 留在存储，当前请求只保留必要索引或不读取 | 当成已经删除，或后续无法找回 |
| E 可回退派生物 | 缓存摘要、检索摘录 | 原文或策略改变后重新生成；以原件校验 | 摘要取代权威原文，循环摘要持续漂移 |

A不是“所有历史用户消息全塞进去”。作者有效决定应有独立权威记录；未结构化的旧约束须先溯源，其他历史按目标摘取。原始长稿本身超预算时，按段落分步完成，不能简单截尾。

## 3. 按场景组织

| 场景 | 核心上下文 | 默认不需要 |
|---|---|---|
| 分析新导语 | 新导语、本轮维度、相关方法、有效限制 | 所有历史二创候选全文 |
| 比较第一与第三个候选 | 两个具体版本的关系/动力/选择/风险、作者偏好和约束 | 其他候选正文及所有报告全文 |
| 结合第一章大概念讨论已选方向 | 已选版本、相关导语与第一章结论、作者限制、当前问题 | 只因时间近而被加入的无关报告 |
| 对比v1/v3 | 两版差异、作者反馈来源、指定比较维度 | 自动将v3当作已选版本 |
| 局部引用真实性检查 | 被核查原文段落、版本、引用原句 | 仅凭摘要作逐字核验 |

## 4. 整理顺序和压缩后记录

先明确对象 → 去重 → 删除当前无关载荷 → 摘取相关证据 → 必要时分块摘要 → 校验 → 重新计数。禁止将超限完整请求直接交给同一模型要求“压缩一下”。

摘要必须记录：原始对象ID/哈希/版本、覆盖段落和未读范围、事实/分析/决定/建议的身份、有效否定条件、重要因果、未解决问题、生成策略及模型、输入输出Token、回查位置。

程序核验权限、ID、版本、范围、引文及决定状态；语义检查关注人物动机、因果和否定含义。自动检查不能替代人工质量评测。

## 5. 停止与恢复原则

- 超过本次硬预算：不发送，先重组。
- 摘要校验失败：不替换旧视图，回到原件重试或分块。
- 建议每次原请求至多两轮重组修复；分块另受累计调用与Token预算约束。此为防循环建议，待验收。
- 无净节省、最小必要材料仍装不下或累计预算耗尽：保留任务对象、已完成结果和未覆盖清单，交付可恢复状态。
- 不自动换模型或删除作者资料来解决预算；不把部分覆盖写成全文完成。

## 6. 验收时要保护的样例

“女主必须主动，不靠男二”压缩后仍保留；“不复合”被作者明确改为“和解”后旧限制不能复活；选定v1而讨论v3不能自动切换已选；作者只采纳截图取证不能连带采纳搬家情节；新第一章不能被旧导语取代。

本清单定义P1/P2应遵循的产品规则，本阶段没有生成或写入任何产品压缩摘要。
