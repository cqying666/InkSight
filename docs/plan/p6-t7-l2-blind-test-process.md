# P6-T7 L2 人工盲测对照流程

> Phase 6 P6-T7 交付物 · 2026-07-03
>
> 对齐 PRD §6.2 三层质量保障体系 — L2 层：每月 5 篇抽样做人工 vs AI 对比；素材提取质量抽查。校准 AI 到人类水平。

## 1. 目标

L1 自动化稳定性测试（每周，已由 `tests/consistency-monitor.ts` 覆盖）保证引擎不退化，但无法发现"AI 系统性偏差"（例如某类钩子总是识别过弱、某类反转节点位置系统性偏移）。L2 层通过人工对照，把 AI 输出与"专家真值"对齐，作为 prompt 迭代与基准库扩展的依据。

L2 与 L1/L3 的关系：
- L1（每周自动）：稳定性 — 同一篇拆 5 次一致性 >85%
- **L2（每月人工）：准确性 — AI vs 人工标注一致率达标**
- L3（持续用户）：有用性 — 用户评分均值 >4 分

## 2. 频率与抽样

| 维度 | 规格 |
|------|------|
| 频率 | 每月 1 次（建议每月第 1 周完成） |
| 抽样数 | 5 篇/月 |
| 抽样来源 | 当月新增拆文库（用户上传 + 运营预拆） |
| 抽样分层 | 覆盖 4 种类型：情节驱动 2 篇 / 情感驱动 1 篇 / 氛围驱动 1 篇 / 混合型 1 篇 |
| 抽样回避 | 不与 L1 周测试集 20 篇重叠（避免数据污染） |
| 抽样锁定 | 抽样当周锁定拆文 prompt 版本，避免月内 prompt 改动影响对照 |

## 3. 评估维度与阈值

对齐 PRD §6.1 质量维度，L2 重点覆盖 L1 测不到的"准确性"维度：

| 维度 | 定义 | 阈值 | 评估方法 |
|------|------|------|----------|
| 类型识别准确率 | AI 类型 vs 人工标注一致率 | >90% | 严格匹配 + 置信度 <0.7 时降级为 mixed 视为半对 |
| 钩子类型准确率 | 开头钩子分类 vs 人工 | >85% | 6 类钩子（悬念/冲突/反常/对话/景物/心理）匹配 |
| 三幕占比偏差 | AI 与人工对三幕边界位置的偏差 | <10% | 中点位置偏差 <10 个百分点 |
| 反转节点位置偏差 | AI 与人工标注反转位置的偏差 | <8% | 反转位置偏差 <8 个百分点，反转数量偏差 ≤1 |
| 情绪曲线形状 | AI 与人工情绪曲线的形状相似度 | >0.7 | Pearson 相关系数（按 10 等分采样点） |
| 结局类型准确率 | AI 与人工结局分类一致率 | >85% | 5 类结局（圆满/悲剧/开放/反转/留白）匹配 |
| 素材提取准确率 | 自动提取的结构模式与人工判断一致率 | >80% | 钩子/反转/情绪曲线/弧光/冲突 5 类分别评估 |
| 处方方向合理性 | 人工评判处方方向是否切题 | >75% | 3 名评估员多数同意制 |

> 阈值参考 PRD §6.1，部分维度（如情绪曲线形状、处方方向合理性）PRD 未给数值，本流程根据短篇创作方法论补充。

## 4. 评估流程

### 4.1 准备阶段（月初第 1 周）

1. **抽样**：从拆文库当月新增作品中分层抽样 5 篇，记录作品 ID、类型、来源
2. **锁定 prompt 版本**：记录当前 prompt hash，评估期间不改 prompt
3. **生成 AI 报告**：对 5 篇分别跑拆解 + 诊断 + 处方，存档 JSON
4. **生成人工真值**：由 1 名评估员（运营或种子用户中资深创作者）独立完成 14 维度标注
   - 标注模板见 §5
   - 评估员不查看 AI 输出，避免锚定偏差

### 4.2 对照阶段

5. **自动维度对照**：对类型/钩子/三幕/反转/结局等结构化维度，用脚本计算 AI vs 人工的偏差
6. **主观维度对照**：对情绪曲线/处方方向等非结构化维度，由 3 名评估员独立打分后多数同意
7. **素材提取抽查**：对 5 篇中每篇抽取自动提取的 5 类素材（钩子/反转/情绪/弧光/冲突），人工评判"是否准确反映原文结构"

### 4.3 报告产出

8. **校准报告**：汇总到 `docs/quality/l2-report-YYYY-MM.md`，含：
   - 抽样列表 + prompt 版本
   - 各维度一致率 vs 阈值
   - 不一致案例分析（含原文片段 + AI 输出 + 人工真值 + 差异说明）
   - 改进建议（prompt 调整 / 基准库扩展 / 降级阈值调整）
9. **归档**：报告提交到 `docs/quality/` 并在 `MASTER.md` 记录

### 4.4 改进闭环

10. **改进优先级**：未达标维度进入下月迭代 backlog
11. **回归验证**：下月 L2 评估时优先复测上月未达标维度
12. **prompt 变更门禁**：若 L2 报告触发 prompt 调整，调整后需跑 L1 一致性测试（5×2）确认不退化，再进 L2 复评

## 5. 人工标注模板

每篇人工真值标注格式（与 AI 输出 schema 对齐，便于脚本对照）：

```yaml
work_id: <作品ID>
title: <标题>
type: <plot-driven | emotion-driven | atmosphere-driven | mixed>
type_confidence: <0-1，人工置信度>

# 骨架层
hook:
  type: <悬念 | 冲突 | 反常 | 对话 | 景物 | 心理>
  strength: <1-5>
  evidence: <原文片段引用>
three_act:
  setup_end_pct: <0-100，铺垫结束位置>
  midpoint_pct: <0-100，中点位置>
  climax_pct: <0-100，高潮位置>
reversals:
  - position_pct: <0-100>
    type: <情节反转 | 认知反转 | 情感反转>
ending:
  type: <圆满 | 悲剧 | 开放 | 反转 | 留白>
event_density: <事件数/千字>

# 血肉层
emotion_curve:
  shape: <先抑后扬 | 双反转 | 持续低位 | 持续高位 | 波浪 | V 型 | 倒 V | 平稳>
  key_points: [<位置%>: <情绪值 -5~5>, ...]
dialogue_ratio: <0-1>
sensory_frequency: <次/千字>
character_arc:
  desire: <主角欲望>
  obstacle: <核心障碍>
  change: <变化方向>
conflict_layers:
  interpersonal: <0-1，占比>
  internal: <0-1>
  environmental: <0-1>

# 风格层（可选，L2 重点不在风格层）
# 句式 / 用词 / 视角 / 时态

# 素材提取评估（每篇 5 类）
material_extraction:
  hook_template:
    accurate: <true | false>
    note: <说明>
  reversal_pattern:
    accurate: <true | false>
    note: <说明>
  emotion_curve_template:
    accurate: <true | false>
    note: <说明>
  character_arc_path:
    accurate: <true | false>
    note: <说明>
  conflict_layer_config:
    accurate: <true | false>
    note: <说明>

# 处方评估
prescription:
  directions:
    - label: <方向名>
      relevant: <true | false>
      actionable: <true | false>
      note: <说明>
```

## 6. 评估员要求

- 主评估员 1 名：负责生成人工真值（14 维度标注）
- 复核评估员 2 名：负责主观维度打分 + 处方合理性判断（3 人多数同意制）
- 资质要求：
  - 短篇创作经验 ≥3 年，或运营内容岗
  - 熟悉 PRD §5.2-5.4 三层 14 维度拆解体系
  - 不参与 prompt 编写（避免自评偏差）

## 7. 自动化支持

L2 流程中可自动化的部分（脚本辅助）：

| 步骤 | 自动化 | 工具 |
|------|--------|------|
| 抽样 | 半自动 | 按类型分层从拆文库随机抽 5 篇（待拆文库后端上线后实现） |
| AI 报告生成 | 全自动 | `npm run teardown -- <work_id>` 单篇拆解 |
| 结构化维度对照 | 全自动 | 待开发 `tests/l2-compare.ts`：输入 AI JSON + 人工 YAML，输出偏差表 |
| 主观维度对照 | 人工 | 评估员阅读 + 打分 |
| 报告汇总 | 半自动 | 模板化 markdown，自动填充结构化维度数据 |
| 改进跟踪 | 人工 | 下月回归验证时人工核对 |

> 当前阶段（拆文库未上线）L2 以文档化流程为主，待运营招募种子用户后启动首次 L2 评估。

## 8. 与 L1/L3 的衔接

- **L1 → L2**：L1 周测试发现的一致性异常维度，进入 L2 月评估重点核查
- **L2 → L1**：L2 触发的 prompt 调整，需通过 L1 回归测试再上线
- **L2 → L3**：L2 未达标的维度，对应模块在 L3 用户评分中重点关注（如处方方向合理性未达标 → L3 关注报告有用评分）
- **L3 → L2**：L3 用户评分低于 4 分的模块，下月 L2 优先抽样该类型作品深挖原因
