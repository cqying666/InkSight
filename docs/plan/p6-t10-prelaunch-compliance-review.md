## 2. 用户上传内容版权

### 2.1 风险描述

InkSight 核心场景是用户上传短篇小说全文进行拆文分析（PRD §5.1 特性 1）。用户可能上传：
- 自己拥有版权的作品（合规）
- 他人版权作品（侵权）
- 平台付费内容（如知乎盐选付费故事，双重侵权：版权 + 平台服务条款）

### 2.2 法律框架

- **《著作权法》第 24 条**：合理使用范围包括"为个人学习、研究或者欣赏，使用他人已经发表的作品"，但平台化服务是否属于"个人"范围存在争议
- **《信息网络传播权保护条例》第 20-23 条**：避风港原则 — 平台收到侵权通知后及时删除的可免责
- **最高法指导案例 263 号**：用户授权导入模式下，平台提供工具不直接提供内容，可主张技术中立

### 2.3 合规要求（上线前必须）

1. **用户协议**：上传时强制勾选"我拥有该作品版权或已获授权"承诺
2. **DMCA/侵权投诉通道**：页面底部提供 `mailto:complaint@inksight.example` 链接，承诺 48 小时内响应
3. **存储策略**：
   - 用户上传内容仅用于当前会话拆文分析，**不长期存储原文**
   - 拆文结果（结构化 JSON）可存储，但不含原文大段引用（证据引用 ≤200 字，符合合理使用）
   - 写后分析产出（用户自己的作品）由用户自主保存，平台不主动留存
4. **付费内容识别**：上传知乎盐选等付费内容时提示"该内容可能受平台服务条款约束，请确认你有权使用"

### 2.4 当前实现状态

- ✅ 上传页支持文件上传（Phase 2 P2-T2/T3）
- ⏳ 用户协议勾选：**待上线前补充**（当前上传按钮直接提交，无版权承诺）
- ⏳ 投诉通道：**待上线前补充**（页脚需加投诉邮箱）
- ✅ 原文不长期存储：当前上传内容仅在会话 sessionStorage 中，关闭即清除

## 3. 隐私与个人信息保护

### 3.1 数据现状

当前阶段（Mock-First + localStorage）：

| 数据类型 | 是否 PII | 存储位置 | 保留策略 |
|----------|---------|----------|----------|
| 匿名会话 ID（sid） | 否 | sessionStorage | 会话级，关闭即清 |
| 行为埋点事件 | 否 | localStorage（`inksight:analytics_queue`） | 上限 500 条，FIFO |
| 上传小说原文 | 否（但含用户创作内容） | sessionStorage | 会话级 |
| 拆文结果 JSON | 否 | sessionStorage | 会话级 |
| 创作工作台内容 | 否（用户作品） | localStorage（`inksight:write_draft`） | 用户手动清除 |
| 素材库 | 否 | localStorage（`inksight:materials`） | 用户手动清除 |

### 3.2 法律框架

- **《个人信息保护法》第 4 条**：个人信息是以电子或者其他方式记录的与已识别或者可识别的自然人有关的各种信息，不包括匿名化处理后的信息
- **《个人信息保护法》第 13 条**：符合下列情形之一的，个人信息处理者方可处理个人信息：…（二）为订立、履行个人作为一方当事人的合同所必需…
- 笔名/作者名属个人信息（PRD §5.5 采集字段含"作者"）

### 3.3 合规评估

- ✅ **不采集 PII**：当前无账号系统，不收集姓名/手机/邮箱
- ✅ **匿名化处理**：sid 为随机生成，不关联个人身份
- ⚠️ **趋势采集的"作者"字段**：属个人信息，真实采集接入时需评估
  - 趋势热力图展示的是聚合数据（题材 × 元素矩阵），不展示单篇作者
  - 元素详情卡"代表作品 Top 3"展示标题 + 平台，**不展示作者名**（建议保持）
- ⚠️ **用户上传小说中的作者署名**：拆文分析不提取作者署名，结果 JSON 不含 PII

- [ ] 隐私政策页（`/privacy`）撰写

## 4. 处方参考案例引用

### 4.1 风险描述

PRD §5.1 特性 7：处方建议每个方向附带"参考案例"。若参考案例为他人版权作品的原文片段，可能构成侵权。

### 4.2 合规要求

- **描述性引用**：参考案例仅描述结构特征（如"某悬疑短篇在第 40% 位置安排认知反转"），**不引用原文**
- **合理使用边界**：证据引用 ≤200 字，注明出处，符合《著作权法》第 24 条合理使用
- **prompt 终审**：上线前确认处方 prompt 不会输出原文片段

### 4.3 当前实现状态

- ✅ 拆文 prompt 证据引用限制在合理范围（PRD §5.2-5.4 已设计）
- ⚠️ 处方 prompt 的"参考案例"字段：**待上线前终审**（需确认 LLM 不会编造或泄漏原文）

### 4.4 待办（上线前阻塞项）

## 5. AI 生成内容标识

### 5.1 风险描述

2023 年起，《互联网信息服务深度合成管理规定》要求深度合成服务提供者对 AI 生成内容进行标识。

### 5.2 合规评估

- InkSight 的 AI 输出为**结构化分析报告**（拆解 + 诊断 + 处方），非"内容生成"（不替用户写小说）
- 处方"三不原则"（不替写/不给唯一答案/不评判）进一步降低风险
- 但报告中的"反直觉发现"和"处方方向"仍属 AI 生成文本

### 5.3 合规要求

- 报告页加"AI 辅助分析"标识（建议在报告头部）
- 处方面板加"AI 生成建议，仅供参考"提示

### 5.4 当前实现状态

- ⏳ 报告页 AI 标识：**待上线前补充**
- ⏳ 处方面板 AI 提示：**待上线前补充**

## 7. 数据跨境

### 7.1 当前阶段

无跨境：所有数据在用户本地浏览器（localStorage）+ LLM API 调用（OpenAI 服务器，已在 `.env.local` 配置）。

### 7.2 LLM API 跨境

- OpenAI API 调用涉及数据出境（用户上传的小说片段发送给 OpenAI）
- **《数据出境安全评估办法》**：累计 10 万人个人信息或 1 万敏感个人信息需安全评估
- 当前阶段无账号系统，无法累计到 10 万，**无需安全评估**
- 后端上线后若用户量增长，需重评

### 7.3 后端上线前待办

- [ ] LLM API 数据出境风险评估（若用户量 <10 万可豁免）
- [ ] 若使用国内 LLM（如智谱/通义），无跨境问题，建议优先
